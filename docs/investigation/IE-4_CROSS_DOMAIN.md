# IE-4 — Multi-Domain (Cross-Domain) Investigation (Implemented)

IE-2 (DNS) and IE-3 (Identity) validated the acquisition→reasoning architecture on
independent domains. IE-4 validates **cross-domain operational reasoning**: two
independent domains participating in one investigation, with evidence correlated
across domains, competing hypotheses eliminated, and confidence reflecting the
cross-domain corroboration — while single-domain and all-off behavior stay
byte-identical.

> **Result:** on `EFIC-IAM-001` (`necessary=[aws_cloudwatch, identity]`), enabling
> Identity + AWS produces one coherent investigation in which the IAM-policy root
> cause (identity) is corroborated by the observed S3 403s (AWS), confidence rises
> 80→86, and the competing `aws_access_denied` + `error_spike_generic` hypotheses
> are eliminated. All-off and single-domain hashes are unchanged.

## What was added

1. **A minimal AWS/CloudWatch domain** (behind `IE_AWS_ENABLED`) — the second
   domain IAM-001 needs. Same 8-link pattern as IE-2/IE-3: `AwsWorker`,
   `aws_cloudwatch` gateway stub, proof-gated probe (Step 3i), `_extract_aws_evidence`,
   `_analyze_aws`. It emits AWS-primary root causes (`s3_throttling`, `az_impairment`,
   `security_group_block`) and a **low-scored** `aws_access_denied` for S3 403s —
   low because a 403 is the *symptom* of an authorization change, so the identity
   domain owns that root cause.

2. **A cross-domain correlation layer** — `_correlate_cross_domain`, the actual
   IE-4 capability. It runs **only when ≥2 IE domains are enabled** (so IE-2/IE-3
   single-domain runs are untouched), before evidence-weighted scoring, and mutates
   only IE-owned hypotheses:
   - **Corroboration**: `iam_permission_revoked` (identity, authZ) + AWS S3 403s →
     the policy denial is corroborated by the observed 403 count; the hypothesis
     gains a cross-domain `evidence_ref` and a bounded, deterministic confidence
     boost (so confidence reflects two independent domains agreeing).
   - **Contradiction / elimination**: the 403-not-5xx pattern contradicts a service
     *outage*, and a cross-domain-confirmed specific root cause outranks the
     undifferentiated `error_spike_generic`, which is weakened out of contention.
   - It returns a correlation record stored on `evidence["_cross_domain_correlation"]`
     for the trace.

## Flag discipline (byte-identical when off)

Every IE-4 path is gated: `AwsWorker` registered only when `IE_AWS_ENABLED`, Step 3i
skipped at the call site, `_analyze_aws` injection skipped, and the correlator gated
on `len(_ie_active_domains()) >= 2`. All IE flags off ⇒ `content_hash =
3e277b87d9bc31db` (the baseline). The EB-2 twin serves the `aws_cloudwatch` channel
and advertises the server only when the flag is on.

## Honest assessment

- The cross-domain "elimination" reinforces ruling out the *generic/undifferentiated*
  hypothesis and the low-scored AWS symptom hypothesis; the EFIC infrastructure
  *traps* (`s3 outage`, `network`) are never generated by the deterministic engine,
  so there is no fabricated hypothesis to eliminate — the honest framing is
  corroboration + confidence + de-ranking the generic alternative, not slaying a
  strawman.
- The confidence boost is bounded and deterministic; it raises confidence within the
  expected band, it does not manufacture certainty.
- Only one cross-domain pair (Identity + AWS) is exercised end-to-end on a real EFIC
  scenario; the correlator is written generically (it also has a DNS+AWS rule) but
  DNS+ThousandEyes remains unexercised because ThousandEyes reasoning (link 8) is not
  built.

## Tests & determinism

`tests/enterprisebench/test_ie4_crossdomain.py` (11) — AWS flag-off inertness, AWS
reasoning, correlation boost + contradiction, no-op without a second domain, the
`_ie_active_domains` gate, and end-to-end cross-domain-corroboration-on-IAM +
all-off-unchanged. Full regression green.

## Recommendation

The multi-domain architecture is validated. Highest-value next work is not more
domains but **making the cross-domain reasoning consumable in production** (the IE
slices remain flag-gated pilots) and **wiring ThousandEyes reasoning (link 8)** so
DNS+ThousandEyes becomes a second, network-layer cross-domain pair. One reviewed,
flag-gated, EB-2-validated increment at a time.
